# WI-09 domain worker boundary

This slice defines an inactive WI-owned worker contract in `worldinterface-worker`. It uses strict, bounded versioned artifacts through the existing effect input, resolved resource, authorization, evidence, and artifact references. Existing record envelopes and `ControlValues` remain unchanged. The process profile definition is pinned to `contracts/sources/wi-fabric-2-worker-execution-profile.yaml` SHA-256 `6523baf56d14dafa4b199c7493dc030461cc061754c180b4c83006308e633986` and full WI-ADR-016 approval `10a13b9c-cbfc-4469-9e03-9011adbdd507`.

`WorkerRequestV1` supplies operation, profile, input, and control bindings. `ResolvedWorkerV1` binds provider, run, adapter, executable, dependencies, configuration, authorization, and controls to the exact request digest. An adapter must use the existing `ImmutableArtifactManifest` and `ResolvedEffect` and persist only the non-secret credential binding. Typed control evidence keeps requested, advertised, applied, and observed states separate. The consumer sees opaque handles and scoped artifact references. Local PID, boot/birth, ownership nonce, process-tree and path data are private adapter facts.

The eventual local transport is a parent-created Unix socketpair with a deliberately passed descriptor, bounded versioned frames and separate logs. `WorkerPort` is transport independent. No socket, process, filesystem adapter, authority path, or production implementation exists in this slice. The test provider is scripted and asynchronous. The process profile permits reviewed executables and non-sensitive input, with finite wall-time and output bounds. Independent worker VM, hostile-code containment, CPU, memory, process-count, network and filesystem enforcement require separate evidence. Mediation and enclosing-instance evidence do not establish those properties.

Provision, start, inspect, terminate, collect-artifacts, and release have typed operation semantics. Command, checkpoint, suspend and resume are unavailable. Acknowledgment differs from observed outcome. Uncertain ownership quarantines a run before replacement. Export validation checks scope, owner, bounds, digest and verifier findings; actual filesystem race and link safety remain process-provider work. Worker completion and receipts are evidence, not application acceptance.

The six assigned WP cases and negative tests are listed in `conformance/wi-fabric-2/worker/coverage.json`. This is domain evidence only. WI-06/WI-08 acceptance, WI-09 integration/process-provider, AB-WI-021, real lifecycle and cleanup, live evaluation authorization, provider qualification, full isolation and parent acceptance remain pending at their assigned milestones. Worker assumptions WP-A01–WP-A08 retain their original owners in the source ledger.
