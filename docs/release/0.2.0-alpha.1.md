# WorldInterface 0.2.0-alpha.1

Release identity: **0.2.0-alpha.1 / v0.2.0-alpha.1**.

Eight new-runtime crates carry the embedded worker proof: protocol, capability,
domain, storage, worker, ingress, egress, and runtime (all `worldinterface-`
prefixed). Rust 1.89.0, Linux x86_64 GNU, Apache-2.0. The legacy root workspace
and its 0.1.x packages are unchanged. ActionQueue is exactly crates.io 0.3.0;
its six resolved packages retain the checksums in `contracts/aq-integration-target.json`.

Preparation exposed a process-discovery race: Linux returns `ESRCH` when a child
is reaped after its `/proc/<pid>/stat` descriptor is opened. Discovery now treats
that read result as departure, as it already does for `ENOENT`. Other read errors
and live identity mismatches still reject ownership. A deterministic unit test
holds the descriptor across reaping and checks both departure and error handling.

The receipt-inspection fixture uses a bounded 15-second attempt budget so that
concurrent journal work does not turn its former one-second budget into an
incidental throughput requirement. A deliberately delayed provider reproduces
the former `RetryWait` failure and now retains completion and an inspectable
receipt. Production budgets and timeout conformance checks are unchanged.

Preparation pins `RUSTUP_TOOLCHAIN=1.89.0` for gates and external archive/consumer
staging, where the checkout's `rust-toolchain.toml` does not apply. The effective
override is recorded in the build environment and checked again by verification.

This is an integration proof pre-release. The embedded worker milestone and
WI-WORKER-G1 through G4 describe reviewed fixture execution, with six bounded
operations, 15000 ms wall time and 65536 retained output bytes. Ordinary use,
production credentials, remote providers, real VM qualification, and supervisor
WI-WORKER-G5 remain unavailable. The authoritative limitations and consumer
obligations ship in `worldinterface-runtime/release/handoff.json`, alongside ten
`release/gates/*.json` records. Closing those records requires reviewed merge
with adopted checks; preparing a release does not grant closure or publication.

`dependencies_digest()` identifies `release/repository-Cargo.lock`, a byte-equal
snapshot of the runtime repository lock. Cargo normalizes the archive's own
`Cargo.lock`; its digest is recorded separately for each archive in the external
release manifest and consumer handoff. Do not substitute those identities.

## Tests in archives and repository

`package-tests.json` is the exhaustive target inventory. Every archive runs
explicit library unit tests and doctests. Retained integration targets are
protocol `control_plane`, capability `scope`, domain `control_plane`, storage
`continuation` and `worker`, and runtime `worker_artifact_crash` and
`worker_artifact_validation`. Storage's C fault injector, shared control support, and unit fixtures
are package-local, with authoritative byte checks.

Repository-only integrations are protocol `canonical`/`ingress`, capability
`flow_registry`, domain `developmental`/`flow`/`transitions`,
storage `control_plane`/`flow`/`stores`, ingress `lifecycle`, egress `domain`,
worker `contract`/`evidence`, and the remaining runtime integration targets (including
`worker_campaign`). These depend on repository conformance, sibling support,
or the exact committed evaluation packet and worker campaign. They remain in
`foundation-test` and `runtime-test`, run before packaging; none is silently
claimed as archive coverage. The inventory names every runtime target explicitly.

## Consumer and worker programs

Copy `examples/downstream-consumer` outside the checkout, then run:

```sh
export WI_WORKER_BUILD_ROOT="$(pwd -P)"
export CARGO_HOME="$WI_WORKER_BUILD_ROOT/cargo-home"
export CARGO_TARGET_DIR="$WI_WORKER_BUILD_ROOT/target"
mkdir -p "$CARGO_HOME" "$CARGO_TARGET_DIR"
export CARGO_HOME="$(cd "$CARGO_HOME" && pwd -P)"
export CARGO_TARGET_DIR="$(cd "$CARGO_TARGET_DIR" && pwd -P)"
export RUSTUP_TOOLCHAIN=1.89.0
export CARGO_BUILD_JOBS=8
cargo +1.89.0 fetch --manifest-path Cargo.toml
cargo +1.89.0 run --locked --manifest-path Cargo.toml
cargo +1.89.0 metadata --locked --format-version 1 > consumer-resolution.json
```

There are exact registry requirements, no path dependencies or patches, and a
standalone workspace. Inspect `manifest_path` for the resolved runtime registry
package and read its `release/handoff.json`, `release/gates/` and lock snapshot.
For a post-publication check use crates.io directly, with no preparation source
replacement. Preserve the generated consumer lockfile and resolution report.

The exports canonicalize paths before Cargo sees them, including an existing
symlink at `cargo-home` or `target`. Preserve those canonical exports for the
worker install; preparation records them in the build environment.
Preparation also canonicalizes temporary-directory environment variables for
repository gates, preserving the runtime store's rejection of symlink components.

Build both worker executables using the same explicit recipe as preparation.
After the fetch above, replace inherited Rust flags with path remappings. Map
each registry source directory, including its registry-id suffix, to the same
logical root; mapping only `registry/src` would retain the variable suffix.
Map staging and target paths too. Map the sysroot's Rust source directory to
`/rustc/<commit-hash from rustc -vV>`, which also matches builds without rust-src
installed. ASCII 31 separates flags so paths can contain spaces. Specific source
mappings come last:

```sh
unset RUSTFLAGS
export CARGO_ENCODED_RUSTFLAGS="$(python3 - <<'PY'
import os
import re
import subprocess
from pathlib import Path
home = Path(os.environ['CARGO_HOME'])
roots = sorted(p for p in (home / 'registry/src').iterdir() if p.is_dir())
assert roots, 'fetch the registry consumer first'
sysroot = Path(subprocess.check_output(['rustc', '--print', 'sysroot'], text=True).strip()).resolve()
rustc = subprocess.check_output(['rustc', '-vV'], text=True)
commit = re.search(r'^commit-hash: ([a-f0-9]{40})$', rustc, re.M)[1]
mappings = [(Path(os.environ['WI_WORKER_BUILD_ROOT']), '/wi/build'),
            (Path(os.environ['CARGO_TARGET_DIR']), '/wi/target'),
            *[(p, '/wi/registry') for p in roots],
            (sysroot / 'lib/rustlib/src/rust', '/rustc/' + commit)]
print('\x1f'.join(f'--remap-path-prefix={source}={dest}' for source, dest in mappings))
PY
)"
cargo +1.89.0 install --locked --version '=0.2.0-alpha.1' \
  --target x86_64-unknown-linux-gnu --profile release \
  --bin wi-process-fixture --bin wi-process-reaper \
  --root "$WI_WORKER_BUILD_ROOT/install" worldinterface-runtime
sha256sum "$WI_WORKER_BUILD_ROOT/install/bin/wi-process-fixture" \
  "$WI_WORKER_BUILD_ROOT/install/bin/wi-process-reaper"
```

The producer executes this route offline through the exact archive registry and
records both digests and sizes in external `consumer-handoff.json`. That record
binds the descriptor, commit, archive hashes, repository and packaged lock hashes,
consumer lock, toolchain, target, profile, path-remapping recipe and actual worker
build environment, including its disposable Cargo home, sysroot, rust-src
availability and encoded flags. The recipe replaces inherited `RUSTFLAGS` and
`CARGO_ENCODED_RUSTFLAGS`. Registry and staging paths are canonicalized before
Cargo runs; preparation and verification refuse workers containing the recorded
build, Cargo-home, target or sysroot paths. Registry
location, staging paths and the sysroot location do not affect the expected
worker digests. Executable digests apply
to that build environment, including its system/linker; they are not universal
reproducibility promises. Compare a consumer's digests under the recorded recipe
and environment, and retain its own measurements if the environment differs.
The operator relays the exact `consumer-handoff.json` bytes and its manifest
SHA-256 through the map's published record to EXV-11; see staging step 4. Consumers
with crates.io-only network access receive that file as an input, verify its
trusted digest, and compare its archive hashes to their registry lockfile.
