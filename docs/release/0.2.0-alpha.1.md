# WorldInterface 0.2.0-alpha.1

Release identity: **0.2.0-alpha.1 / v0.2.0-alpha.1**.

Eight new-runtime crates carry the embedded worker proof: protocol, capability,
domain, storage, worker, ingress, egress, and runtime (all `worldinterface-`
prefixed). Rust 1.89.0, Linux x86_64 GNU, Apache-2.0. The legacy root workspace
and its 0.1.x packages are unchanged. ActionQueue is exactly crates.io 0.3.0;
its six resolved packages retain the checksums in `contracts/aq-integration-target.json`.

This is an integration proof pre-release. The embedded worker milestone and
WI-WORKER-G1 through G4 describe reviewed fixture execution, with six bounded
operations, 15000 ms wall time and 65536 retained output bytes. Ordinary use,
production credentials, remote providers, real VM qualification, and supervisor
WI-WORKER-G5 remain unavailable. The authoritative limitations and consumer
obligations ship in `worldinterface-runtime/release/handoff.json`, alongside ten
`release/gates/*.json` records. Closing those records requires reviewed merge
with adopted checks; preparing a release does not grant closure or publication.

`dependencies_digest()` identifies `release/repository-Cargo.lock`, a byte-equal
snapshot of the runtime repository lock. Cargo normalizes the archive's own
`Cargo.lock`; its digest is recorded separately for each archive in the external
release manifest and consumer handoff. Do not substitute those identities.

## Tests in archives and repository

`package-tests.json` is the exhaustive target inventory. Every archive runs
explicit library unit tests and doctests. Retained integration targets are
protocol `control_plane`, capability `scope`, and storage `continuation` and
`worker`. Storage's C fault injector, shared control support, and unit fixtures
are package-local, with authoritative byte checks.

Repository-only integrations are protocol `canonical`/`ingress`, capability
`flow_registry`, domain `control_plane`/`developmental`/`flow`/`transitions`,
storage `control_plane`/`flow`/`stores`, ingress `lifecycle`, egress `domain`,
worker `contract`/`evidence`, and all runtime integration targets (including
`worker_campaign`). These depend on repository conformance, sibling support,
or the exact committed evaluation packet and worker campaign. They remain in
`foundation-test` and `runtime-test`, run before packaging; none is silently
claimed as archive coverage. The inventory names every runtime target explicitly.

## Consumer and worker programs

Copy `examples/downstream-consumer` outside the checkout, then run:

```sh
cargo +1.89.0 fetch --manifest-path Cargo.toml
cargo +1.89.0 run --locked --manifest-path Cargo.toml
cargo +1.89.0 metadata --locked --format-version 1 > consumer-resolution.json
```

There are exact registry requirements, no path dependencies or patches, and a
standalone workspace. Inspect `manifest_path` for the resolved runtime registry
package and read its `release/handoff.json`, `release/gates/` and lock snapshot.
For a post-publication check use crates.io directly, with no preparation source
replacement. Preserve the generated consumer lockfile and resolution report.

Build both worker executables using the same explicit recipe as preparation:

```sh
cargo +1.89.0 install --locked --version '=0.2.0-alpha.1' \
  --target x86_64-unknown-linux-gnu --profile release \
  --bin wi-process-fixture --bin wi-process-reaper \
  --root /absolute/empty/install-root worldinterface-runtime
sha256sum /absolute/empty/install-root/bin/wi-process-fixture \
  /absolute/empty/install-root/bin/wi-process-reaper
```

The producer executes this route offline through the exact archive registry and
records both digests and sizes in external `consumer-handoff.json`. That record
binds the descriptor, commit, archive hashes, repository and packaged lock hashes,
consumer lock, toolchain, target, profile and environment. Executable digests apply
to that build environment, including its system/linker; they are not universal
reproducibility promises. Compare a consumer's digests under the recorded recipe
and environment, and retain its own measurements if the environment differs.
