# ActionQueue baseline alignment — AQ-BASELINE-ALIGNMENT-1

This is a normative downstream integration amendment, not an ActionQueue implementation change. It resolves AQ-facing API sketches and assumptions against the supplied **ActionQueue 0.2.0 / AQ-CONT-1 source**, conformance package revision **16**. When an earlier planning sketch differs, use this amendment and the pinned source; constitutional domain ownership, original work-item identities, dependencies and full exit obligations remain unchanged.

Resolve and verify an immutable implementation commit/build before production integration. Consumer conformance and publication remain **not run / not verified**.

The upstream base stack label `STACK-2026-07-20-CLEAN-1` and downstream `STACK-2026-07-25-FOUNDATIONAL-2` are intentionally distinct. The shared developmental diagnostics profile is byte-identical. No new AQ primitive or delegation of domain authority to AQ is introduced.

## 1. Admission and application outboxes
Use the public `EnsureTaskRequest` containing AdmissionKey, persisted TaskSpec/TaskId, dependencies and causal/control context. The high-level request computes **CanonicalAdmissionV2**; an extra digest argument is not part of that request. Lower-level AdmissionPlan digest validation must not be confused with this API. Persist the stable TaskId and complete request before the first call, not only after an acknowledgment: same key plus a newly generated TaskId is a digest conflict, not a safe retry.

`EnsureTaskOutcome::Created` and `AlreadyExists` return **sequence, task_id, admission_key and digest only**. Discover RunIds separately through authorized inspection, including pagination, bounded response sizes and stale-cursor restart. Treat an acknowledgment loss or uncertain 503 as possibly committed, recover and retry the identical request. Do not infer absence of effects from absence of an acknowledgment.

An admission atomically creates one task and its bounded initial runs, dependencies and parent/causal linkage. It is not an arbitrary multi-task transaction. Limits include 64 dependencies, 64 initial runs, 64 admitted children per disposition, 64 child wait targets, 64 consumption entries, 32 emitted signals and child depth 8. Larger domain graphs need explicit bounded staging/coordination; preserve domain outbox obligations across those stages.

## 2. Signals, early events and a single active wait
Producer ingress uses `AdmitSignalRequest`; trusted `SignalIngressContext` supplies tenant, received time and control attribution before producing the durable SignalEnvelope. Deduplication is by **(host tenant, SignalId)** with matching canonical producer content, not an unrelated dedup_key. SignalSequence is not a WAL sequence or timestamp.

Every authoritative event that owes a wake must atomically create its domain outbox obligation **whether or not a coordinator is currently Awaiting**. Outbox delivery retries a stable producer request. For signal-before-wait recovery use **AnyRetained with an exact correlation filter**; uncorrelated AnyRetained is invalid. Signals are non-consuming and can fan out to multiple matching waits. After processing a wake, persist and advance the handled SignalSequence for a subsequent `After` wait, or use a fresh correlation generation; repeatedly re-arming identical AnyRetained can repeatedly select the same retained signal. Domain state remains authoritative when catching up delayed outbox events.

A run has **one active wait**. A target is either one exact SignalFilter/FirstMatch or a bounded direct-children target. Filter tenant, namespace and kind are exact; None tenant means unscoped only. Optional correlation/source constrain when present. There is no principal filter, wildcard, payload predicate or arbitrary OR-filter list. Normalize related event meanings into a domain-owned signal stream and reload authoritative state, or use explicit bounded child coordinators. Do not invent an AQ multi-wait primitive.

`After(SignalSequence)` matches only later signals. Deadlines are inclusive absolute epoch seconds, but **the first committed eligible resolution wins**; wall-clock expiry does not retroactively defeat a signal. Reconciliation checks retained signals before unresolved deadlines. Choose ResumeWithTimeout, FailRun or CancelRun explicitly.

## 3. Resume, disposition and execution versus business success
One durable wait resolution does not imply one handler invocation. ResumeContext can be redelivered as Initial, Retry or Recovery with the original context identity; wakes include signal, children, deadline, control and administrative forms. Domain handlers must reload authority, deduplicate and make acceptance/effects idempotent. Awaiting/Suspended close physical attempts without spending the failure cap; interrupted execution and actual failure accounting remain distinct.

Disposition combinations are constrained. **Complete** allows output, emitted signals and consumption, but no checkpoint, wait or child admissions. **Awaiting** requires a wait, allows checkpoint/children/signals/consumption and has no output. **Suspended** allows checkpoint and consumption but not wait/output/children/signals. Failure/timeout statuses do not commit arbitrary subordinate effects. Invalid local proposals become minimal terminal failure; no hidden partial child/signal/checkpoint effects may leak.

At wait capacity, local Awaiting fallback is terminal `wait_capacity` and discards subordinate effects. A rejected remote result keeps the active attempt/fence for correction while valid. Uncertain writes or stale ownership are not this fallback. Lowering wait limits to zero prevents new active waits but does not invalidate existing resolvable waits.

Required children must be terminal, not necessarily successful; detached children have different closure/cascade obligations. AQ task success does not certify that every run or domain work product succeeded. AQ Complete, a worker exit and an external effect receipt are not independent WI/EXO acceptance.

## 4. Causality, authority and artifacts
Use the bounded typed causal vocabulary and eight opaque reference slots rather than a generic policy map. Opaque references are attribution, **not authorization**. Children inherit AQ-owned parent linkage with only permitted overrides. Typed Task/Run/Attempt causation must resolve in the same queue/tenant; between EXO's cognition queue and WI's effect queue use an opaque external reference rather than foreign local IDs.

HostControlContext is deliberately host-created, not a caller-deserializable grant. Scope and authorization apply before duplicate acknowledgments; public caller attribution does not replace trusted host context. Inspection remains scoped and redacted. Disclosure requires both request and trusted policy; inspection does not expose arbitrary payloads/locators or replace artifact retrieval.

TaskPayload is opaque bytes bounded to 64 KiB, **not a DataRef field**. For large task input, serialize a small application-owned immutable locator envelope into those bytes. Where APIs actually accept DataRef (signals, checkpoints and output), AQ records it but does not fetch external content. The owning application supplies authorization, hash verification, lifetime/availability, retention and consistent artifact backup.

## 5. Hosting, versions, storage and resource lifetime
Continuation, DAG, hierarchy and child admission are available in the base feature set. `workflow` is needed for cron, not for every Flow. Budget/actor/platform capabilities are explicit; platform implies actor. Store features are fixed at initialization, not upgraded by loading a broader binary.

Embedding must install and dispatch application handlers. Running the daemon alone does not automatically execute WI or EXO handlers. **HTTP /api/v2** is separate from **remote actor protocol version 1**, whose result contract revision and fence/digest checks also apply. Native/embedded proof does not certify remote/platform parity.

Use two independent queue domains/stores (EXO cognition, WI effects), one writer per store. The external host supervisor is not a third cognitive/effect queue, and there is no cross-WAL atomic transaction. Current format versions are manifest 1, WAL frame 1, snapshot 9 and projection 9. Stores are fresh-lineage only. Complete retained WAL is required for restore/replay even when snapshots exist; snapshot-only restore and WAL compaction are unsupported. Signal retirement stops matching but does not reclaim retained WAL/resident signal content. Provide backpressure, capacity planning and alarms rather than unsupported deletion/compaction claims.

Backup/restore must hold the required exclusive/offline posture and coordinate domain records and artifacts. Cancelling already succeeded/failed work is append-free AlreadyTerminal (HTTP 409); retrying cancellation of an already-canceled target is an append-free acknowledgment. Neither is a late cancellation cascade from a finished prerequisite. Queue cancellation does not prove external worker termination or rollback of an effect. Awaiting normally releases concurrency keys; explicit `HoldWhileAwaiting` retains them, and released keys are reacquired before running. Bound process-worker lifetimes separately until confirmed cleanup.
